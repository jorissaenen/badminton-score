# The design sprint board

The board: **https://claude.ai/artifact/GyQ2HrA7UYe9FYH1JER1d1** ("Skoor redesign"), a Design-type
artifact on a canvas. Files: `project/project.json` (the board list: file, x/y position, size,
title like "25 · Screens, court") and one `project/<Name>.dc.html` per board (phone boards
390 wide; TV and watch boards larger). Watch boards were generated by a script (Apple / Wear /
Garmin × Start, Serve, Score, Refused, Offline, Ends, Game, Over, Menu, Settings).

## Working on it

1. **Read it first** in each session: `Artifact` with `action: "read"` and the URL. That returns
   the type's own instructions and where the files are saved; follow those (they win over this
   page). List files with `scope: "files"` when needed; read only the boards you change.
2. Edit the local copies, then publish to the **same URL** with `root` set to the folder holding
   `project/`, passing only the changed files. Never publish without `url` (that makes a new
   board) and never use `force`.
3. A new board: add its file and an entry in `project.json`, placed in the row of its topic,
   numbered after the last one.
4. Boards show the real app's look: black background, Barlow Condensed for titles and scores,
   flip tiles, the house colours (see `skoor-ui-check`), English texts from `alpha/js/lang/en.js`.

## Comments from the owner

Comments arrive as notifications or via the `ArtifactComments` tool (load it with ToolSearch).
For each: change the board (and the app, when it's about built screens), reply on the comment in
one line saying what changed, and resolve it. Several comments: handle them all, then publish
once. Keep a short list of what was changed for the final message.
